# Политика безопасности «Камыш» (Kamish)

## Основные принципы защиты

1. **Аутентификация, управление сессиями и паролями**:
   - **Хэширование паролей**: Используется стойкий криптографический алгоритм **Argon2id** (библиотека `argon2`). Пароли пользователей никогда не сохраняются в открытом виде.
   - **Таблицы `users` и `auth_sessions`**: Сессии генерируют уникальный токен (UUID) со сроком жизни (TTL 7 суток).
   - **Принудительная смена дефолтного пароля**:
     - При первой инициализации создаётся администратор `admin` со статусом `must_change_password = true`.
     - Защитный middleware `auth_middleware` перехватывает все маршруты `/api/v1/*`.
     - Если пароль не был сменён, middleware блокирует доступ ко всем бизнес-эндпоинтам кодом **403 Forbidden** (`code: PASSWORD_CHANGE_REQUIRED`), пропуская только смену пароля (`/api/v1/auth/change-password`), проверку сессии (`/api/v1/auth/session`) и выход (`/api/v1/auth/logout`).
     - После успешной смены дефолтного пароля старые сессии аннулируются, флаг `must_change_password` снимается, и шаг `auth` мастера настройки помечается как завершённый (`completed`).
   - **Методы передачи сессии**:
     - Cookie `kamish_session=<token>` (`HttpOnly`, `Path=/`, `SameSite=Lax`, `Max-Age=604800`).
     - Заголовок `Authorization: Bearer <token>`.
     - Заголовок `X-Session-Token: <token>`.
     - Query-параметр `?token=<token>` (для рукопожатия WebSocket на `/api/v1/events`).
   - **Белый список без аутентификации**:
     - Только публичный статус узла `GET /api/v1/status` и эндпоинт входа `POST /api/v1/auth/login`.

2. **Границы облачных сервисов и изоляция**:
   - **Строгий запрет на облачные STT и TTS**:
     - Распознавание речи (STT) и синтез (TTS) выполняются **исключительно локально на устройстве** (Vosk, Piper, RHVoice, оффлайн WAV-генератор тонов).
     - Передача аудиопотока пользователя или микрофонных записей на сторонние облачные серверы категорически запрещена.
   - **Облачные сервисы (AI и мультимедиа)**:
     - Antigravity CLI (`agy`) взаимодействует с внешней языковой моделью через изолированный дочерний процесс (stdin/stdout). Токены авторизации CLI хранятся в защищенном каталоге устройства и не отдаются через API.
     - YouTube Music используется исключительно для потокового аудио и поиска метаданных; секреты авторизации (cookies/OAuth) маскируются.
   - **Изоляция ИИ-инструментов**:
     - Antigravity CLI не имеет прямого доступа к Shell (`/bin/sh`, `/bin/bash`), демонам или файловой системе.
     - Выполнение команд колонки происходит только через строго типизированный реестр из **14 инструментов** (*Tool Registry*).

3. **Защита конфиденциальных данных и маскирование**:
   - Пароли Wi-Fi сетей (WPA2/WPA3 PSK), токены сессий, cookies сервисов и приватные ключи VLESS / Happ никогда не выводятся в логах (`tracing`).
   - В API конфиденциальные данные маскируются (`has_password: true`, `is_configured: true`).
   - В тестах и dev-окружении физический аудиовыход принудительно глушится (`KAMISH_MUTE_AUDIO=1`).

4. **Сетевая безопасность**:
   - Панель управления и API доступны только в локальной сети устройства (LAN) или через защищенный VPN-туннель.
   - Точка первичной настройки (`kamish-setup` AP, 192.168.4.1) автоматически отключается после успешного подключения к домашней сети Wi-Fi.
   - Защита от переполнения буфера и атак внедрения команд за счет типобезопасности Rust.

5. **Идемпотентность и валидация**:
   - Все входящие HTTP-запросы валидируются через парсеры Serde.
   - Исключено выполнение команд, сформированных прямой конкатенацией пользовательских строк.
